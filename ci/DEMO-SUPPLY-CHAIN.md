# G1: controlled open-source use for an isolated demo

The maintainer clarified on 2026-10-21 that this is a demo intended to show how
to handle open-source supply-chain risks, and that no external report should be
made. This policy replaces the requirement to obtain upstream fixture/revocation
confirmation before running the isolated demo. It does not claim that unknown
historical credentials are harmless or revoked.

## Specific inherited-history disposition

Policy `G1-DEMO-HISTORY-20261021` applies only to the exact metadata inventory in
`demo-history-inventory.json`, bound by a SHA-256 constant in `demo_history.py`.
It contains **2,282 records at 1,931 distinct locations/spans** from the imported
fork. 2,190 records belong to the pinned upstream baseline ancestry; 92 belong
to imported branches that are not the selected demo baseline. This distinction
is recorded per entry. No values, tokens or private keys are stored in the
inventory. The existing separately proved checksum exclusion remains the only
entry in `.gitleaksignore`.

The full-history scanner still runs with pinned default rules and disabled inline
allow comments, and still returns findings. Its finding count and raw exit code
remain visible in sanitized CI evidence. A separate policy decision accepts the
known inherited risk **only for this synthetic, isolated demo**. The gate requires
exact finding identities and multiplicities: any new commit/path/rule/span,
changed inventory or missing historical coverage fails. Reintroducing an old
value in a new commit also fails. Scanner errors or absent evidence fail closed.
This is an explicit risk disposition, not a clean-secret-scan claim or an
automatic trust decision for everything inherited from upstream.

The policy expires at **2026-11-21 00:00 Asia/Jakarta**
(`2026-11-20T17:00:00Z`). Changing the scope, inventory or expiry requires a new
explicit review. It cannot authorize production, registry publishing, signing,
or deployment. Those operations remain unavailable to current CI workflows.
P2 may use the demonstrated baseline only with synthetic data and the same
isolation; production eligibility must be evaluated separately before release.
There is no requirement or authorization to contact upstream or a cloud provider.

## Enforced containment

- Issuer and token keys are generated anew using JDK JCA P-256. Acceptance checks
  four distinct keys across two generations, restrictive file/directory modes,
  and refusal to overwrite an existing key file. Holder keys are generated by
  the actual wallet during the real protocol flow. No upstream key or cloud
  credential is copied into the demo runtime.
- Services and the Python HTTP runner share a Docker **internal bridge**, with
  no host-published ports or additional networks. External DNS forwarding is
  disabled; a connection to a reserved documentation address must fail because
  there is no external route. No real provider authentication is attempted.
- Actual Docker inspection must prove non-root/read-only execution, dropped
  capabilities, no privilege escalation, exact disposable bind sources/targets,
  and no cloud/GitHub credential environment variables. The HTTP runner receives
  no private-key mount. Wallet temporary execution remains limited to its native
  SQLite loader; other temporary mounts use noexec.
- Images carry `org.nusacred.scope=synthetic-isolated-demo-only` and evidence marks
  them ineligible for production. Only local image configuration digests are
  recorded; no registry manifest or production deployment is claimed.

## Supply-chain acceptance and rejection evidence

Existing mandatory controls remain: source-built/source-manifest-verified COSE,
13 COSE tests and three selected fresh-key mdoc tests; strict reviewed Gradle
hashes/locks; reviewed npm archives with strict peer validation and offline
lifecycle/build; pinned Actions/JDK/tools/base image; complete-source SCA including
dev; actual resolved-runtime and assembled-image scans/SBOMs; and the real
issuer/wallet/verifier credential harness. High/Critical findings remain blocking.
No newly discovered artifact hash is accepted by verification runs.

`test-supply-chain-controls.py` exercises the real verifiers against changed
inputs: a new generated secret with an inline allow comment, old material in a
new commit, scanner failure, missing history, changed inventory, policy expiry,
production scope escalation, unreviewed ignore, changed build lock and npm/Gradle
injection even after their enclosing manifest digest is updated. Positive reviewed
npm and Gradle inputs must pass. Test values are disposable and non-provider;
raw reports and values are never uploaded.

After the real image flow, six mutations of captured Docker inspection evidence
must be rejected: external bridge, host port, root, added capability, external DNS
and host credential mount. These tests never weaken the live containers. The
sanitized outcomes accompany source-bound image/key/isolation evidence in CI.

This demonstrates concrete prevention and detection controls for dependency
substitution, unreviewed inputs, accidental credential additions and unsafe demo
execution. It does not establish that all upstream code is benign, verify all
publisher attestations or revoke third-party credentials. G1 passes for this demo
only when all required checks and these containment checks pass on the same head.
